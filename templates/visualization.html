How SecureOT Works

Understanding Oblivious Transfer and the IKNP Oblivious Transfer Extension protocol.

01. System Overview

Sender

Provides two messages: M0 and M1.

→
Oblivious Transfer

Performs the cryptographic protocol and protects the receiver's selection.

→
Receiver

Obtains only the selected message.

02. Basic 1-out-of-2 Oblivious Transfer

Oblivious Transfer (OT) is a cryptographic protocol in which a sender provides two messages, but the receiver obtains only one of them without revealing which message was selected.

STEP 01

Sender Setup

The sender generates a private Diffie-Hellman exponent and a corresponding public value.

C = ga mod p

The sender keeps the private exponent secret and shares the public value with the receiver.

STEP 02

Receiver Selection

The receiver selects a choice bit:

b ∈ {0, 1}

Based on this choice, the receiver constructs a cryptographic response using its private exponent and sends the response to the sender.

STEP 03

Key Generation and Encryption

The sender derives two different shared secrets and uses them to encrypt the two messages separately.

  • One encryption key protects M0.
  • Another encryption key protects M1.
  • AES-GCM provides authenticated encryption.
STEP 04

Selected Message Decryption

The receiver derives the shared secret corresponding to its selected choice and decrypts only the matching ciphertext.

b = 0 → M0
b = 1 → M1

The receiver does not obtain the other message's decryption key through this protocol.

03. IKNP Oblivious Transfer Extension

The IKNP OT Extension protocol allows a large number of Oblivious Transfers to be constructed using a relatively small number of initial Base OTs.

Core idea: Instead of performing an expensive public-key operation for every message pair, IKNP uses a small set of Base OTs and efficient pseudorandom expansion to construct multiple OTs.
PHASE 01

Base OT Setup

The extended receiver generates two random seeds for each security parameter position.

(ki0, ki1)

The extended sender receives one seed from each pair according to its randomly selected base-OT choice bit.

In this implementation, 128 Base OTs are used.

PHASE 02

Pseudorandom Expansion

The receiver expands both seeds into pseudorandom bit strings using a cryptographic expansion function.

ti0 = G(ki0)
ti1 = G(ki1)

These expanded strings form the rows of the receiver's matrix.

PHASE 03

Matrix Construction

The receiver uses its choice vector r to construct the U matrix.

ui = ti0 ⊕ ti1 ⊕ r

The U rows are transmitted to the sender. The sender combines them with its selected seeds to construct its Q matrix.

PHASE 04

Key Derivation

The sender extracts columns from Q and derives two separate keys for each extended transfer.

K0 = H(qj)
K1 = H(qj ⊕ s)

The receiver derives the key corresponding to its selected message using its own matrix column.

PHASE 05

Encrypted Message Transfer

The sender encrypts both messages independently using their derived keys and sends the ciphertexts to the receiver.

C0 = AES-GCM(K0, M0)
C1 = AES-GCM(K1, M1)

The receiver uses its selected key to decrypt the corresponding ciphertext.

Result: Multiple OT transfers using a small number of Base OTs.
